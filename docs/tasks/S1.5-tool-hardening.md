# S1.5 Tool hardening (task spec for OpenCode)

Branch: `s1-5-tool-hardening`. Do exactly this task and nothing else. Run the tests, show the results, then stop.

## Why (evidence from live test 3, 18 Nov 2026)
- Telnyx MCP tools are assistant-level, not per-node. The model called `reserve_technician` in the Details node, before it had the caller's name (BUG-006).
- The model sent the caller's SIP address (`xxxx@sip.telnyx.com.au`) as `call_ref` instead of the resolved `{{call_ref}}` (`v3:...`). `isCallRef` rejects `@`, so every call was `invalid_input` (BUG-009).
- In the Reserve node it called `create_job` instead of `reserve_technician`, with an invented `job_id` copied from `call_ref` (BUG-010, BUG-007).
- Logs showed `call_ref: null` and no failing field, so the cause was only visible in the transcript (BUG-011).
- Rule: the server must not depend on the model carrying IDs. Prompts cannot scope tools.

## Rules
- Only touch the files listed. No new dependencies. Never log argument values, names, addresses or phone numbers.
- Failures stay data (`ok:false`), never thrown. Every failure result carries `next:"fallback"` and `retry:false`.
- Tests with the real actor classes on fake storage, as in the existing tests. Existing tests that encode old behaviour may be updated; say which.

## Changes

### 1. Server-side call identity (`src/routes/mcp.ts`, `src/lib/validate.ts`, `src/tools/index.ts`)
- `tools/call` params may contain `_meta`. Pass a third argument `ctx: { meta_conversation_id?: string }` to every handler (`ToolHandler = (args, env, ctx)`).
- Add `resolveCallRef(args, ctx)` in `validate.ts`, in this order:
  1. `ctx.meta_conversation_id` if present (look in `_meta.telnyx_conversation_id`, then `_meta.conversation_id`; VERIFY the real key name with a live call, see item 6).
  2. Else the model's `args.call_ref` if it is a non-empty string of at most 200 characters.
  3. Else return null (tool returns `invalid_input`).
- Whatever the source, turn it into a safe ref: `"c:" + first 32 hex chars of SHA-256(value)`. This always satisfies `CALL_REF_RE`, so a SIP address or `v3:` string no longer causes a rejection. Keep `isCallRef` for the admin routes.
- All four tools call `resolveCallRef` and ignore a mismatching model value silently.

### 2. Server-side job id (`src/tools/create_job.ts`, `release_technician.ts`, `index.ts`)
- `job_id` is no longer an input the model must send. Make it optional in both schemas and ignore it. Read the real `job_id` from the JobActor record found by the resolved `call_ref`.
- `create_job` and `release_technician` use `job.job_id` from the actor. Keep the existing `no_active_reservation` behaviour when there is no job.
- `reserve_technician` still returns `job_id` and `technician_name` (the model may mention the technician name; it does not need to carry the id).

### 3. Reserve requires the caller details (`src/tools/reserve_technician.ts`)
- Add required inputs `customer_name` (cleanText, 80), `address` (cleanText, 200), `callback_number` (`normalisePhone`; a SIP address must fail). Validate only; do not store them in this task.
- Effect: the model cannot call reserve before it has the details, so an early call returns `invalid_input` with `next:"fallback"` and a field hint (item 5) instead of reserving.

### 4. Tool descriptions and schema descriptions (`src/tools/index.ts`)
Replace descriptions with exactly this intent, in plain words:
- `reserve_technician`: "Reserve an on-call technician. Call this once, only after you have confirmed the caller's name, address and callback number and know the urgency, trade and suburb. Do not call it earlier. If it fails, do not retry."
- `create_job`: "Record the caller's details for the technician. Call once, only after reserve_technician succeeded. Do not retry if it fails."
- `release_technician`: "Release a reserved technician when the call cannot proceed. Call only if a technician was reserved. Use one reason from the list. Do not retry."
- `lookup_customer`: leave as is.
- Add a `description` to every property. `call_ref`: "Use the call_ref value from your instructions. It is never a phone number or SIP address. Optional; the server can identify the call itself." Add `pattern`/`maxLength` where sensible. Do not add a `pattern` to `call_ref` (the server accepts any string).

### 5. Failure results and logging (`src/tools/*`, `src/lib/log.ts`, `src/routes/mcp.ts`)
- Every failure result: `{ ok:false, reason, next:"fallback", retry:false }`, plus `bad_fields: string[]` listing only field names that failed validation (names, never values). Applies to `invalid_input` and `no_active_reservation` too.
- Add optional fields `bad_fields` (string, comma-joined names) and `meta_keys` (string, comma-joined key names of `_meta`, names only) to `LogFields` and the fixed log line. Log them on `mcp_call`. Log the resolved `call_ref` (the safe `c:` ref) so rejected calls are no longer null.
- Log `call_ref_source` (`meta` | `args` | `none`).

### 6. Verification log
- Add `V-0xx` to `docs/verify-log.md`: "MCP `_meta` key names Telnyx sends on tools/call: PENDING a live call; read them from `mcp_call.meta_keys`". Do not guess. If `meta_keys` is empty after a live call, record that `args.call_ref` is the only source.

### 7. Escalation number (`src/routes/dv.ts`, `.env.example`)
- Remove the hard-coded `FALLBACK_NUMBER_SPOKEN`. Read secret/env `FALLBACK_NUMBER` via `readConfig`. Speak it in digit groups with the existing `spoken` helper (or a small equivalent). If unset, return `fallback_number_spoken` as "the office" and log a warn `fallback_number_unset`. Add `FALLBACK_NUMBER` to `.env.example` as a placeholder only. Never commit a real number.
- Replace the `call_ref = "unknown"` default with `"u:" + 12 random hex chars`, so two degraded calls never share a reservation.
- Business name stays "Harbour Trades After-Hours" (the greeting hard-codes it).

### 8. Remove the temporary test routes (`src/index.ts`)
- Delete `/kv-test` and `/actor-test` and their handlers/tests. Keep the findings already in `docs/verify-log.md`. Confirm `/health`, `/dv`, `/mcp`, `/admin/*` remain.

### 9. Bug journal (`docs/bug-journal.md`)
Append BUG-006 to BUG-011 in the existing format (When/where, Symptom, Evidence, Hypotheses ruled out, Root cause, Fix, Signal, What we would add to catch it faster, Status):
- BUG-006 Reserve fires in the wrong node (tools are not per-node). Evidence: transcript row with `flow_node_id: details` and a reserve tool call before the name was asked. Fix: item 3 and 4.
- BUG-007 Fallback loop: 11 `create_job` calls with invented job ids (test 1). Fix: item 2, 5.
- BUG-008 Fallback said details were logged (false claim). Fix: Portal prompt wording (no code).
- BUG-009 Model sends the SIP address as `call_ref`. Evidence: tool-call arguments in Conversation History; `invalid_input` in logs. Fix: item 1.
- BUG-010 Model calls `create_job` in the Reserve node instead of `reserve_technician`. Fix: item 2, 4.
- BUG-011 Rejected calls hide the cause (`call_ref` null, no field). Fix: item 5. Signal: only found by reading the transcript.
Status for all: fixed in S1.5, pending live re-test.

## Tests to add or update
- `resolveCallRef`: meta wins over args; a SIP address becomes a `c:` ref; empty returns null; same input gives same ref.
- Reserve: missing `customer_name`/`address`/`callback_number` returns `invalid_input` with `bad_fields`; a SIP address as `callback_number` fails; valid input reserves; replay with a different model `call_ref` but the same meta id is idempotent.
- `create_job` and `release_technician` work without `job_id`; `no_active_reservation` carries `next:"fallback"`.
- `/mcp` logs `meta_keys` names (not values) and the resolved ref; `/dv` with and without `FALLBACK_NUMBER`; `/kv-test` and `/actor-test` return 404.
- Run: `tsc --noEmit`, the scrub check, no `console.log` outside `src/lib/log.ts`, full test suite. Report the counts.
