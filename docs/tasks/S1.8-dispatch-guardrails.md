# S1.8 Dispatch guardrails (task spec for OpenCode)

Branch: `s1-8-guardrails`. Do exactly this task and nothing else. Run the tests, show the results, then stop.

## Why (evidence from live tests 5 and 6, 19 Nov 2026, and a code review)
- Prompts cannot be the only guardrail. The model's urgency and trade come from noisy speech-to-text ("water is drying out fast" was classed `urgent`; a gas smell must never be below `emergency`).
- `reserve_technician` loops `TECH_POOL` in order and ignores the job's trade, so a plumber can be reserved for a gas or electrical job. There is no skill or licence check.
- `normalisePhone` accepts any 8 to 15 digits, so a short or fake callback number is accepted (for example `0412345` becomes `61412345`). A callback that cannot be dialled is a failed dispatch.
- `create_job` on an already briefed job silently overwrites the confirmed details with whatever the model sends next.
- Job records (name, address, phone) are kept forever.
- Design rule for emergencies: HARD-reject only what makes the job impossible (no way to call back). For doubtful but usable data, accept the job and attach FLAGS for a human to review. A false rejection on an emergency call is worse than a flagged job.

## Rules
- Only touch the files listed. No new dependencies. Never log argument values, names, addresses or phone numbers (log field names and flag names only).
- Failures stay data (`ok:false`, `next:"fallback"`, `retry:false`, `bad_fields`). Do not change tool names, schemas or descriptions in `src/tools/index.ts`. Do not return flags, urgency changes or technician identity to the model.
- Tests use the real actor classes on fake storage, as in the existing tests. Existing tests that encode old behaviour may be updated; say which.

## Changes

### 1. Technician profiles and eligibility (`src/lib/pool.ts`, `src/tools/reserve_technician.ts`)
- Mock data in `pool.ts` (the README says business systems are mocked). Add `TECH_PROFILES: Record<TechId, { name: string; trades: readonly Trade[] }>` and a third technician. Use exactly:
  - `tech-01` Jordan: plumbing, gas
  - `tech-02` Casey: electrical, hvac
  - `tech-03` Riley: plumbing, other
  Keep `TECH_POOL`, `TECH_NAMES` and `ETA_MINUTES` exported so existing code compiles. A trade listed for a technician means skilled AND licensed for it (gas and electrical are licensed work in Australia). Suburb or area matching is out of scope (documented limitation).
- `reserve_technician`: build the candidate list from technicians whose `trades` include the (effective, see item 2) trade, in pool order. Try only those. If none can be reserved, return `no_technician_available`. `attempt` is the 1-based position within the eligible list. The replay path (existing job) is unchanged.
- Log `technician_id` as before. Log `eligible_count` on the `mcp_call` or `reserve_attempt` line (add an optional numeric field to `LogFields` only if one does not exist; counts only).

### 2. Severity and trade floor (`src/lib/validate.ts`, `src/tools/reserve_technician.ts`)
- Add `applyFloors(trade, urgency, summary)` returning `{ trade, urgency, raised: boolean, corrected: boolean }`.
- If `summary` (lower-cased, whole words) matches any of: `gas`, `smoke`, `spark`, `sparks`, `sparking`, `burning`, `electrocuted`, `shock`, `flood`, `flooding`, `burst`, `sewage`, `fire`, `carbon monoxide`: urgency becomes `emergency`.
- If it matches `gas`: trade becomes `gas`. (Conservative on purpose: a gas hot water complaint is routed to a gas-licensed technician and treated as an emergency; say so in the decision log.)
- If trade is `gas` urgency is always `emergency`.
- The effective values are what is stored and used for eligibility. Log `urgency_raised` / `trade_corrected` as `outcome` or event names only, no values.
- The model's own value is never LOWERED by this function.

### 3. Soft validation flags (`src/lib/validate.ts`, `src/tools/reserve_technician.ts`, `src/actors/JobActor.ts`)
- Hard rejects (`invalid_input`, field name in `bad_fields`), only for `callback_number`:
  - After `normalisePhone`, if it starts with `61`, it must be exactly 11 digits. (This rejects `0412345`.)
  - Reject emergency or service numbers: `000`, `112`, `106`, and any number of 6 or fewer digits.
  - Reject a number whose digits are all the same.
  Non-AU numbers that already pass `normalisePhone` stay accepted (the caller may be abroad).
- Flags (accept the job, never reject), computed from the cleaned inputs:
  - `address_no_house_number`: no digit anywhere in `address`.
  - `address_short`: fewer than 8 characters.
  - `name_short`: `customer_name` shorter than 2 characters.
  - `suburb_numeric`: `suburb` contains a digit.
- `JobActor.open` takes an optional `flags: string[]` and stores it on the record. Add a `flags?: string[]` field to `JobRecord`. Names only, no values. Log the flag names (comma-joined) on `job_opened`.
- Flags are never returned to the model.

### 3b. Keep what was confirmed at reservation (`src/actors/JobActor.ts`, `src/tools/reserve_technician.ts`, `src/tools/create_job.ts`)
Why: evidence F10 (`docs/portal/consistency.md`): the model sent `create_job` without `contact_phone` in one of two live calls, so the confirmed callback number was lost. The number was already validated and normalised at reservation; keep it.
- `JobActor.open` also takes optional `customer_name`, `address` and `contact_phone` (the normalised callback). Store them on the record under those names. They are personal data: never log them, and the retention alarm (item 5) covers them.
- `create_job`: if the job already has a stored `contact_phone`, keep it and ignore the `contact_phone` argument (first confirmed value wins, same rule as item 4). If none is stored, use the argument as today.
- `create_job`: treat `hazards` of `none`, `no`, `nil`, `n/a` or `not applicable` (trim, ignore case and trailing punctuation) as not provided. Do not store it.
- Do not change tool schemas or descriptions.

### 4. First write wins on briefing (`src/actors/JobActor.ts`, `src/tools/create_job.ts`)
- If the job is already `briefed`, `create_job` returns the same success result (`ok:true`, same `job_id`, same `reference_spoken`) and does NOT overwrite the stored details. Log `brief_replay` (no values).
- The first confirmed details are the record.

### 5. Retention (`src/actors/JobActor.ts`)
- When a job is opened, set an alarm for `created_at + JOB_RETENTION_DAYS` (config via `readConfig`, default 7, accept integers 1 to 90). `alarm()` deletes the stored job record and logs `job_expired` (no values). It must be idempotent (alarm delivery is at-least-once). If the fake storage in the tests cannot set alarms, stop and report instead of working around it.
- Do not remove the alarm when a job is briefed or released; the record still expires.

### 6. Decision log and bug journal (`docs/decisions.md`, `docs/bug-journal.md`)
- Append D19 to `docs/decisions.md`: "Guardrails in code, not prompts: severity and trade floors, technician eligibility by licensed trade, hard reject only for an undiallable callback, flags for the rest, first-write-wins briefing, 7 day retention". Include the conservative-gas rule and the limitation that area matching is not built.
- Append BUG-023 to `docs/bug-journal.md` in the existing format: "Model classified a sink leak as `urgent` after speech-to-text mangled the caller's words" (Evidence: transcript of the 19 Nov 05:42 UTC call, `urgency: "urgent"` for "water is drying out fast"). Root cause: urgency trusted from the model. Fix: item 2. Signal: found by reading the transcript. Status: fixed in S1.8, pending live re-test.

## Tests to add or update
- `applyFloors`: gas keyword raises urgency and sets trade; `flooding` raises urgency; a value is never lowered; whole-word matching (`gaslight` does not match `gas`).
- Reserve: a `gas` job reserves `tech-01` only, never `tech-02` or `tech-03`; an `electrical` job reserves `tech-02`; a `hvac` job reserves `tech-02`; a `plumbing` job reserves `tech-01` then `tech-03` when `tech-01` is held; a trade nobody has (none after the held ones) returns `no_technician_available` with `next:"fallback"`.
- Callback: `0412345` fails with `bad_fields:["callback_number"]`; `000`, `112` and `0000000000` fail; `0400123456` passes; an international number (`+442071234567`) passes.
- Flags: an address without a digit reserves successfully and stores `address_no_house_number`; flags never appear in the tool result.
- Stored callback: reserve with callback A, then `create_job` with no `contact_phone` -> record holds A; `create_job` with a different `contact_phone` -> record still holds A. Hazards `none` / `No.` are not stored; `gas smell` is stored.
- Briefing: second `create_job` with different details returns the same job and the stored details are unchanged.
- Retention: opening a job sets an alarm; running `alarm()` twice deletes once and does not throw.
- Run: `tsc --noEmit`, the scrub check, no `console.log` outside `src/lib/log.ts`, the full test suite. Report the counts.

## Out of scope (do not do)
Area or suburb matching, a per-caller duplicate guard (needs the caller hash in the MCP context), the technician briefing or warm transfer, KV changes, latency (S1.9), any Portal or workflow change.
