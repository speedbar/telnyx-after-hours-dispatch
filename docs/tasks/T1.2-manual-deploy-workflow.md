# T1.2 Manual deploy workflow (task spec for OpenCode)

Branch: `t1-2-manual-deploy`, cut from main after T1.1 is merged. Do exactly this task and nothing else. Run the checks named below, show the results, then stop.

## Goal
One GitHub Actions workflow that deploys the `dispatch` function by hand. It never runs on push or pull request. A person starts it from the Actions tab and types `deploy` to confirm, then it runs the same checks as CI and ships. There is no approver, because the repo has one maintainer.

## Files
- Create `.github/workflows/deploy.yml`.
- In `.github/workflows/ci.yml` change only the `name:` line, to `Checks: typecheck, scrub, tests`. Change nothing else in it.
- Do not change anything under `src/`, `tests/`, `scripts/`, `package.json` or `telnyx.toml`.

## The workflow
- Name `Deploy to Telnyx Edge (manual)`. Trigger: `workflow_dispatch` only, with one required string input `confirm` (description: `Type deploy to confirm`). Both jobs run only when `inputs.confirm == 'deploy'` (`if:` on each job). Top-level `permissions: contents: read`. A `concurrency` group `deploy` with `cancel-in-progress: false`.
- First comment line: `# Manual deploy. Runs only when started by hand and confirmed by typing deploy. Deploys go live, so check CI is green first.`
- Job `checks`: ubuntu-latest, `actions/checkout@v4`, `actions/setup-node@v4` with node 22 and `cache: npm`, then `npm ci`, `npm run typecheck`, `npm run check:scrub`, `npm test`.
- Job `ship`: `needs: checks`, ubuntu-latest, no `environment`. Env `TELNYX_EDGE_VERSION: v0.5.18` at job level.
  1. `actions/checkout@v4`.
  2. Install the CLI: download `https://github.com/team-telnyx/edge-compute/releases/download/${TELNYX_EDGE_VERSION}/telnyx-edge-${TELNYX_EDGE_VERSION}-linux-amd64.tar.gz` with `curl -fsSL`, extract with `tar xz` into a temp dir, find the `telnyx-edge` binary with `find` and `sudo install -m 0755` it into `/usr/local/bin/`. Then run `telnyx-edge --version`. Telnyx's page names unversioned "latest" URLs as 404, so keep the pinned version.
  3. Authenticate: a step with `env: TELNYX_API_KEY: ${{ secrets.TELNYX_API_KEY }}` running `telnyx-edge auth api-key set "$TELNYX_API_KEY"`, then `telnyx-edge auth status`. The CLI does not read the variable by itself. Never use `set -x` or `echo` the key.
  4. `telnyx-edge ship --timeout 10m`.
  5. `curl -fsS --max-time 20 https://dispatch-b823b5bf-9.telnyxcompute.com/health` and print the body.

## Rules
- No secret values anywhere. The workflow reads `secrets.TELNYX_API_KEY` only.
- Pin actions to the major versions above. No other third-party actions.

## Check
- Parse the file: `python3 -c "import yaml,sys; yaml.safe_load(open('.github/workflows/deploy.yml')); print('yaml ok')"`.
- `grep -n "on:" -A3 .github/workflows/deploy.yml` must show only `workflow_dispatch`.
- Do not run the tests again beyond that. Report in under 100 words.

## Human steps (not OpenCode)
1. Telnyx Portal: create a new API key for CI (note its permissions; VERIFY scope). Revoke it after the demo.
2. GitHub: Settings, Secrets and variables, Actions, New repository secret `TELNYX_API_KEY`. Paste the key there and nowhere else.
3. Run it once at a quiet time: Actions, deploy, Run workflow, type `deploy`. Then check `/health` and make one test call.
