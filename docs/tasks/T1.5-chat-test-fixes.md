# T1.5 Chat-test fixes (wrong assertions, harness gaps, shared state)

Branch: `t1-5-chat-test-fixes`. AGENTS.md rules apply (do exactly this slice, no `src/` edits, never overwrite an existing test, do not run the live chat-test, do not commit).

## Why

The 24 Nov full run with `--repeat 3` passed 6 of 12 scenarios. Reading the output, most failures are not model faults:

1. Phone assertions are wrong. `tokenMatch` needs a non-alphanumeric boundary, so the value `"0400"` never matches the digits-only `"0400123456"` that the model sends. Seen in H-01, H-02 and G-01 on 9 of 12 runs.
2. Urgency assertions check the model's own argument. `reserve_technician` applies severity floors (S1.8, `applyFloors`), so `urgent` from the model is raised to `emergency` by the server. Seen in H-02 (1/3) and H-03 (1/3).
3. The scripted caller has no route for "Is the problem at ...?" or "Is the address ...?" (the confirmation wording after cfg-10). The caller replies "Sorry, can you say that again?" three times and the run stops with `caller_script_unmatched`. Seen in H-01, H-02, H-03.
4. Shared live state. Each booking scenario takes the only technician for a trade (a 90 s hold, then a 30 min busy period after an accept), so the next scenario gets `no_technician_available`. Seen in H-01, H-02, G-01.
5. E-03 asserts `tools_called_exactly: []`, but a spurious `release_technician` (harmless, the server answers `no_active_reservation`) fails it. The real requirement is that nothing is booked.

## Changes

Files: `tests/chat/scenarios.json`, `scripts/chat-test-lib.ts`, `scripts/chat-test.ts` if needed, `tests/chat-test-lib.test.ts` (add tests, do not overwrite).

1. In H-01, H-02, G-01 change every assertion with value `"0400"` (reserve_technician.callback_number, create_job.contact_phone) to `["0400", "0400123456"]`. Add a test that `tokenMatch` accepts the digits-only form through this list.
2. In H-02 and H-03 change `reserve_technician.urgency` from `"emergency"` to `["urgent", "emergency"]`. Leave H-01 and G-01 at `"emergency"`.
3. In the confirmation route (the one that says "Yes that is right." / "Yes.") of H-01, H-02, H-03 and G-01, add these `when` phrases: `"is the problem at"`, `"is the address"`, `"just to check"`, `"let me check"`, `"read that back"`. Check that none of them also matches a question the assistant asks that should go to a different route.
4. Add an optional assertion `tools_not_called?: string[]` (fails if any listed tool was called), with a unit test. In E-03 replace `tools_called_exactly: []` with `tools_not_called: ["reserve_technician", "create_job"]`.
5. Add an optional reset step. If the environment variable `ADMIN_TOKEN` is set (read it like `TELNYX_API_KEY`, never print it), before every scenario that has a `caller` block, POST to `<function URL>/admin/tech` with header `x-admin-token` and body `{"tech_id":"tech-01","method":"clearDispatch"}`, then the same for `tech-02` and `tech-03`. The body key is `tech_id`. If `ADMIN_TOKEN` is not set, skip the step and print one line saying so.
