## Spec: src/lib/log.ts
One JSON object per line on stdout. This file is the ONLY place in src/ that may call console.log.

Types (export them):
- LogLevel = "info" | "warn" | "error"
- Component = "dv" | "mcp" | "actor" | "events" | "ops"
- Outcome = "ok" | "fail" | "degraded" | "rejected"
- LogFields: component (required) and event (required, string); optional: level (default "info"), request_id, call_ref, caller_hash, node, tool, outcome, latency_ms, error, attempt, technician_id, job_id. There is deliberately NO field for a phone number.

Functions (export them):
- formatLine(fields: LogFields, now: Date = new Date()): string
  Returns JSON.stringify of an object with EXACTLY these keys in this order: ts (now.toISOString()), level, request_id, call_ref, caller_hash, component, node, event, tool, outcome, latency_ms, error, attempt, technician_id, job_id. Any field not supplied is null. If error is longer than 300 characters, truncate it to 300.
- log(fields: LogFields): void  ->  console.log(formatLine(fields))
- newRequestId(): string  ->  crypto.randomUUID()
- callerHash(e164: string, salt: string): Promise<string>  ->  SHA-256 (crypto.subtle.digest) of the string salt + e164, as lowercase hex, first 12 characters.
- timed<T>(fn: () => Promise<T>): Promise<{ result: T; latency_ms: number }>  ->  runs fn and returns its result with elapsed whole milliseconds (use performance.now(), rounded; never negative). If fn throws, let the error propagate.

## Spec: src/lib/sig.ts
Telnyx webhook signature check (Ed25519). Signed message is the string `${timestamp}|${rawBody}`. Headers (read by the caller, not by this file): telnyx-signature-ed25519 (base64) and telnyx-timestamp.

Export:
- type VerifyResult = { ok: true } | { ok: false; reason: "missing_headers" | "stale_timestamp" | "bad_signature" | "bad_key" }
- async function verifyTelnyx(rawBody: string, signatureB64: string | null, timestamp: string | null, publicKeyB64: string, nowMs: number = Date.now()): Promise<VerifyResult>
Behaviour, in this order:
1. If signatureB64 or timestamp is null or empty -> { ok:false, reason:"missing_headers" }.
2. Parse timestamp as an integer number of SECONDS since the epoch (add a comment: TODO(VERIFY) confirm the unit against a real Telnyx webhook in S1.2/S2.1). If it is not a finite integer, or Math.abs(nowMs/1000 - ts) > 300 -> "stale_timestamp".
3. Decode publicKeyB64 (standard base64, must be 32 bytes) and import it with crypto.subtle.importKey("raw", bytes, { name: "Ed25519" }, false, ["verify"]). Any failure (bad base64, wrong length, unsupported algorithm) -> "bad_key". Do not add a fallback library; if the runtime does not support Ed25519 the reason is "bad_key" and we will log it as a bug.
4. Decode signatureB64 (standard base64) and call crypto.subtle.verify("Ed25519", key, signatureBytes, new TextEncoder().encode(`${timestamp}|${rawBody}`)). Invalid base64 or a false result -> "bad_signature"; true -> { ok: true }.
The function must never throw. Wrap each step so every failure becomes a VerifyResult.

## Tests (node:test and node:assert/strict; no other libraries)
tests/log.test.ts:
1. formatLine output parses as JSON, and Object.keys equals exactly the 15 keys above in order.
2. With only { component:"dv", event:"dv_in" }: level is "info" and every other field except ts, component, event is null; ts equals the passed-in Date's ISO string.
3. An error string of 500 characters is truncated to 300.
4. callerHash("+61412345678", "salt") is 12 lowercase hex characters, is the same on a second call, differs for a different salt, and does not contain the digits of the phone number.
5. newRequestId matches /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/.
6. timed returns the function's result and a latency_ms that is a non-negative integer.
tests/sig.test.ts (generate a test keypair with crypto.subtle.generateKey({name:"Ed25519"}, true, ["sign","verify"]); export the raw public key and base64-encode it; sign with crypto.subtle.sign; fixed nowMs for determinism):
1. valid signature, timestamp equal to now -> { ok: true }.
2. body changed by one character -> bad_signature.
3. timestamp 301 s old -> stale_timestamp; 299 s old -> ok (sign for that timestamp); 301 s in the future -> stale_timestamp.
4. signatureB64 null, and timestamp "" -> missing_headers.
5. publicKeyB64 = "not-base64!!" -> bad_key; a valid base64 string that decodes to 31 bytes -> bad_key.
6. signatureB64 = "###" -> bad_signature.
7. timestamp "abc" -> stale_timestamp.
