## src/lib/validate.ts
- cleanText(v: unknown, max: number): string | null. Must be a string. Remove control characters (\u0000-\u001F, \u007F), collapse whitespace runs to one space, trim. Return null if empty or longer than max (reject, do not truncate).
- isCallRef(v): /^[A-Za-z0-9:_\-.=]{1,128}$/. isJobId(v): /^J[A-Z0-9]{5}$/.
- oneOf<T extends string>(v: unknown, list: readonly T[]): T | null.
- normalisePhone(raw: unknown): string | null. Returns digits only, no plus. Strip spaces, dashes, dots, parentheses. "+<digits>" keeps the digits; "0<digits>" becomes "61" + the rest; digits starting "61" stay. Result must be 8 to 15 digits, else null.
- jobIdFromCallRef(callRef: string): Promise<string>. Deterministic: "JA" + 4 characters taken from the SHA-256 of callRef (crypto.subtle, first 4 bytes, each byte mod 30) using the alphabet "ABCDEFGHJKMNPQRSTVWXYZ23456789". Same call_ref -> same job id.
- spoken(jobId: string): string. Letters and digits separated by single spaces, e.g. "J A 4 F 7 C".

## Tool contract (src/tools/*.ts, registry in src/tools/index.ts)
Each tool file exports a handler (args: unknown, env: ToolEnv) => Promise<ToolResult>. ToolResult is plain JSON with an `ok` boolean. src/tools/index.ts exports the ToolEnv type and TOOLS: Array<{ name, description, inputSchema, handler }>. ToolEnv: DIRECTORY?, TECH?, JOBS? as optional namespaces { idFromName(name: string): <small local stub interface> } plus an index signature, like SeedEnv. A missing namespace throws (the route turns that into an internal error). inputSchema is a JSON Schema object with properties, required, enums and maxLength matching the caps below, additionalProperties false. Descriptions are one or two plain sentences telling the assistant when to call the tool; no secrets, no internal detail. Unknown extra args are ignored.
Caps: call_ref isCallRef; suburb 60; summary 200; customer_name 80; address 200; details 500; hazards 200; contact_phone via normalisePhone (store the digits).

1. lookup_customer { phone } -> { ok:true, found:false } | { ok:true, found:true, name, address, site_notes?, after_hours_contract } | { ok:false, reason:"invalid_input" }. Call DIRECTORY (instance "directory").lookup(digits, "dispatch_enabled") and use only the customer string. Parse it as JSON inside try/catch (garbage -> found:false). Keep only name and address (cleanText 80 / 200), site_notes (cleanText 200, optional) and after_hours_contract (=== true). Drop every other field.
2. reserve_technician { call_ref, urgency: "emergency"|"urgent", trade: "plumbing"|"electrical"|"gas"|"hvac"|"other", suburb, summary } -> { ok:true, job_id, technician_id, technician_name, eta_minutes, hold_expires_at (ISO), attempt } | { ok:false, reason:"invalid_input"|"disabled"|"already_closed"|"no_technician_available", next:"fallback" }.
   Steps: validate; job_id = jobIdFromCallRef(call_ref); in parallel DIRECTORY.flag("dispatch_enabled") and JOBS(call_ref).get(). Flag "false" -> disabled. Existing record: state released -> already_closed; reserved or briefed -> call TECH(existing.tech_id).reserve({ call_ref, job_id: existing.job_id, ttl_s }) and, if ok, return success with the existing job and technician (idempotent), otherwise no_technician_available. No record: for each id in TECH_POOL in order call TECH(id).reserve({ call_ref, job_id, ttl_s }); the first ok wins (attempt = position + 1); then JOBS(call_ref).open({ job_id, tech_id, urgency, trade, suburb, summary }); if open is not ok, release that hold with TECH.release and return its reason mapped to the allowed list. None ok -> no_technician_available. ttl_s from readConfig(env, "DISPATCH_HOLD_TTL_S"): integer 1..600 else 90.
3. create_job { call_ref, job_id, customer_name, address, contact_phone?, details, hazards? } -> { ok:true, job_id, reference_spoken } | { ok:false, reason:"invalid_input"|"no_active_reservation"|"hold_expired", next? }.
   Steps: validate (job_id isJobId); JOBS(call_ref).get(); null, other job_id or state released -> no_active_reservation. If state is "reserved", read TECH(job.tech_id).status() and require held_for.call_ref == call_ref, held_for.job_id == job_id and expires_at > now, else hold_expired (next:"fallback"). If state is already "briefed" skip that check (replay). Then JOBS.brief(...), mapping its reason. reference_spoken = spoken(job_id).
4. release_technician { call_ref, job_id, reason: "declined"|"no_answer"|"caller_hung_up"|"error" } -> { ok:true, released:boolean, next_technician_available:boolean } | { ok:false, reason:"invalid_input" }.
   Steps: validate; JOBS(call_ref).get(); if it matches job_id and is reserved or briefed, in parallel TECH(job.tech_id).release({ call_ref, job_id }) and JOBS.release({ job_id, reason }); released = either returned released true. Unknown or mismatched job -> released:false (never an error). Then next_technician_available = any TECH_POOL member whose status().status is "available" (query them in parallel). Safe to call repeatedly.
