# T1.6 Admin reset that also clears a hold, and reset before every repeat

Branch: `t1-6-reset-hold`, started from `t1-5-chat-test-fixes` (or from main once T1.5 is merged). AGENTS.md rules apply (do exactly this slice, never overwrite an existing test, do not run the live chat-test, do not commit).

## Why

T1.5 reported that `clearDispatch` only deletes `dispatched_for`. A technician that is only `held` (a 90 s hold from a booking scenario) is untouched, so the next scenario can still get `no_technician_available`. T1.5 also resets once per scenario, before its repeats, so repeats 2 and 3 of the same scenario share state with repeat 1.

## Changes

Files: `src/actors/TechnicianActor.ts`, `src/routes/tech.ts` only if needed, `scripts/chat-test.ts`, and new tests (add to existing test files, do not overwrite).

1. `TechnicianActor.clearDispatch` also clears `held_for` and sets `status` back to `available` when the technician is `held` or `dispatched`. It must not change `off_shift`. It returns what it cleared (`{cleared: true, was: "held" | "dispatched"}` or `{cleared: false}`). Keep the existing response fields that tests rely on.
2. Nothing else about reserve, hold, release, expiry or dispatch changes. A real call must behave exactly as before. Add tests: held then clearDispatch gives available; dispatched then clearDispatch still works; off_shift is untouched; a later reserve succeeds.
3. In `scripts/chat-test.ts` run the technician reset before every repeat of a caller scenario, not once per scenario. Print `technician reset sent` only when at least one request returned an HTTP 2xx; otherwise print `technician reset failed` (never print the token).
4. One line in `docs/edge-cases.md` is not needed. Add a line to `docs/decisions.md` only if you change a decision; do not otherwise edit docs.

## Do not

- Do not add a new route. Do not weaken the `x-admin-token` check.
- Do not touch the ring, SMS or `/dv` code.

`npm run typecheck`, `npm test`, `npm run check:scrub`. Then `git status --short` must list only the files above plus this spec.
