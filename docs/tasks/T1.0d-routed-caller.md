# T1.0d Routed caller replies (branch t1-0-chat-harness, after T1.0c)

Test tooling only. No `src/` change. Do this after T1.0c is built and the human has committed it.

## Why
Scripted user turns are sent in a fixed order. When the assistant asks its questions in a different order, the caller answers the wrong question (H-02 run 3: the address was given in reply to the electrics question) and the run tests nonsense. The caller should answer what was just asked.

## Goal
A scenario can describe the caller by an opening line and keyword routes. The harness answers each assistant reply from the routes. Scenarios that use `turns` keep working unchanged.

## Scenario shape
A scenario has either `turns` (as now) or `caller`:
```
"caller": {
  "opening": "I can smell gas in my kitchen.",
  "routes": [ { "when": ["kw", ...], "when_not": ["kw", ...], "scope": "question", "say": ["first reply", "next reply"] } ],
  "unmatched": "Sorry, can you say that again?",
  "max_turns": 12
}
```
`parseScenarios` must reject a scenario that has both `turns` and `caller`, or neither, and a `routes` entry without a non-empty `when` and `say`.

## Rules
1. Send `opening` first.
2. After each assistant reply, choose the next caller line: take the last sentence of the reply that ends in "?" (the "question"; if there is none, the whole reply). Lower-case it. Walk `routes` in file order; the first route where any `when` keyword is a substring, and no `when_not` keyword is, wins. A route with `"scope": "reply"` is matched against the whole reply instead of the question.
3. `say` is a list. The nth time a route fires, use its nth entry; after the last entry, repeat the last.
4. If no route matches, send `unmatched` and count it. A third unmatched reply in one run stops the run with the failure `caller_script_unmatched` and the last assistant reply (200 chars). Print that failure as "harness gap, not necessarily an assistant fault".
5. Stop when the reply contains "goodbye" (T1.0c rule), or after `max_turns` caller turns.
6. Print routed lines as `USER (routed): ...`.
